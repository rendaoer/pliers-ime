# 使用：按键与输入行为

[← README](../README.md) · 相关：[配置](config.md) · [词库](dictionary.md) · [踩坑](pitfalls.md)

组词时输入框旁边弹出候选框：敲 `nihao` → 候选框里是「你好 你号 尼豪 …」，空格上屏选中的那个。

## 按键表

| 按键 | 行为 |
| --- | --- |
| `a`–`z`（小写） | 攒进 buffer，用 `set_preedit_string` 显示为预编辑文本 —— 打字中途**不会**往应用里塞任何字符 |
| 空格 | 有内容就把**选中的候选**提交（`nihao` → 你好；只匹配了前面一段的候选会分段上屏，见[分段上屏](#分段上屏--记性)），否则当普通空格转发给应用 |
| `←` `→` / `Tab` / `Shift+Tab` | 挪选中的候选（绕圈）。**挪出这一页会自动翻页**；组词当中方向键不去动输入框里的光标 |
| `↑` `↓` / `,` `.` / `-` `=` / `PageUp` `PageDown` | 整页翻，页内位置保持。**上下就是翻页** —— 候选框是横排的，所以左右管"沿着这一行挪"、上下管"换一行"（`-` `=` 是微软拼音的习惯） |
| `1`–`9` | 选**这一页**的第几个上屏；这一页没那么多就什么也不做 |
| 其他符号（`/` `;` `'` `[` `]` `0` …） | **先把选中的候选上屏，再把符号转给应用** —— 顺序反了的话屏幕上会变成 `,你好` |
| 标点 `,` `.` `?` `!` `;` `:` `(` `)` `[` `]` `"` … | 中文模式 + **[中文标点](#中文标点)**打开时打成全角（`，` `。` `？` `！` …），一步上屏（`nihao,` → 「你好，」）；关掉就按半角处理，其中 `,` `.` 还是翻页键 |
| 大写字母 `A`–`Z`（Shift / Caps Lock） | 没在组词 → 原样转发；**正在组词 → 并进预编辑**，整串当英文原文，空格/回车原样上屏 |
| 回车 / 小键盘回车 | 有内容就原样提交，**不**把回车给应用（免得顺手提交表单） |
| Esc | 有内容就取消这次组词，这个键谁也不给（免得顺手退出全屏） |
| 退格 | 删掉一个字符 |
| `Del` | 删掉**自己拼出来的**那个候选 —— 见 [`Del`：删掉自己拼出来的词](#del删掉自己拼出来的词) |
| `Ctrl` + 空格 | **切中英文**（这个键不给应用）。正在组词的半截拼音会先上屏，不会消失。想换成轻按 Shift 或两个都要，见[配置](config.md#输入习惯engine) |
| Ctrl / Alt / Super + 任何键 | **不组词**，原样转发（Ctrl+A 全选、Ctrl+C 中断、Alt+F 菜单……） |
| 其他键 | 用虚拟键盘原样转发，普通打字不受影响 |

不认识的拼音（`aaaa`）空格时原样上屏，不会被吞掉。

## 只有小写字母参与匹配

大写字母（Shift 或 Caps Lock 打出来的）一个都不查表：

* **没在组词**时按大写 → 直接原样转发给应用，Caps Lock 打英文就是普通英文输入；
* **正在组词**时按大写 → 这个字母并进预编辑，整串从此变成"英文原文"：
  `n` 之后按 `Shift+N`，输入框里就是 `nN`（**不会**先蹦出「你」再补个 N），
  候选框收起来，空格/回车把 `nN` 原样上屏；
* 英文原文串里继续敲的字母、数字、符号也并进这一串：`nN2/`、`nNihao` ——
  大写之后接着打小写也不会回头去匹配中文；
* 所以 Caps Lock 打开时打 `NIHAO` 就是五个大写英文字母，一个候选都不出
  （等于暂时把中文输入关掉，跟常见输入法一样），也不会"打 NIHC 一路蹦出「你」「你好」"。

两边为什么不一样：没有组词时把按键直接转过去最省事；组词当中应用正处在"预编辑"状态，
往里塞字符顺序会乱（也实测过应用对它反应不可靠），所以只能并进预编辑里一起上屏。
协议层的细节在[踩坑](pitfalls.md)第 2、4 条。

## 中英文切换

**Ctrl + 空格** 切换（中文输入法的老习惯），切换时在光标处弹一个小方块显示「中」/「英」：

| 模式 | 行为 |
| --- | --- |
| 中文 | 现在这样：字母进组词，空格上屏候选 |
| 英文 | 输入法等于不存在：**所有按键原样转发** —— 打英文、写代码、按快捷键都不受影响 |

提示只是复用候选框画的一个方块（不带序号）：**按下下一个键、或者过 0.6 秒，它就自己收掉**
（所以切完模式不打字，它不会一直挂在光标那儿挡着看）；
**切换时正在组的半截拼音会先上屏**（原样提交原始字母，不做转换）—— 切到英文常常就是因为
"这一串想打英文"，把它留在输入框里比丢掉有用。

```toml
[engine]
# 可以写多个，也可以只留一个；空数组 [] = 不要切换键（那就一直是中文）
toggle_keys = ["ctrl+space", "shift"]   # shift = 轻按一下（按下到抬起之间没按别的键才算）
start_mode = "chinese"                  # 也可以 "english"：启动就进英文
indicator = true                        # 不想要那个「中」/「英」提示就设 false
```

为什么不做成"自动识别英文"：猜错了比不让切更烦人。要打英文时按一下 Ctrl+空格，是确定的。

## 中文标点

中文模式下把半角标点打成全角（搜狗/fcitx 的老规矩），组词当中还会先把候选上屏：

```
nihao,   →   你好，        ← 一步到位：候选 + 全角逗号一起 commit
,        →   ，            ← 没在组词也一样
. ? ! ; : ( ) [ ] { } < > " ' \ _ ^ $ ~   →   。？！；：（）【】「」《》“‘、——……￥～
```

`-` `=` `@` `#` `%` `&` `*` `/` 这些不换（`-` `=` 还是翻页键）。**英文模式下永远是半角**。

```toml
[engine]
# 中文标点：中文模式下 , → ，/ . → 。/ ? → ？…
chinese_punctuation = true
```

关掉的话 `,` `.` 会退回"翻页键"的角色，标点原样转发给应用。运行中改：
`pliers set engine.chinese_punctuation false`（临时）或 `pliers config set engine.chinese_punctuation false`（写进文件）。

## 分段上屏 + 记性

打长串拼音时**不要求一次匹配完**：候选里既有整串的结果，也有"只匹配前面一段"的。
挑中前面那段就先把它上屏，剩下的接着选 —— 挑几次就把一句话拼完了。

```
nihao ma                →  [你好吗] [你号码] [你好] [倪浩] …
                                     ↑ 整句（库里没有「你好吗」时按词拼的）
                                              ↑ 只匹配前面 nihao 的分段候选

↓ ↓ 空格                     挑「你好」→ 上屏，预编辑里剩 ma
   空格                     挑「吗」  → 上屏，这次输入结束

nihao ma 空格           →  你好马        ← 下一次打同一串键，他自己拼的这句话直接排第一
```

分段**最低能细到一个字**：`nihaoma` 里既有「你好」（一次吃 5 个字符），也有「你」（只吃 2 个）——
想一个词一个词地选、还是一个一个字地选都行，剩下的拼音一直留着接着组：

```
woshiyigexuesheng  →  [我是一个学生] [卧室一个学生] [我是一个] [我] [握] [窝] [卧] …
                                                              ↑ 长串也照样给到第一个字
```

前缀是这么挑的：**从长到短找第一个查得到词的分段**（那就是"前面一整段"），
再补上**最短的单音节那段**。所以长句子里既能一次选「天气」，也能一个字一个字地选「天」——
`tmqizfmeyh`（天气怎么样）里 `tmqizfme`、`tmqizfm` 都查不到词，一路往下找到 `tmqi` 才是「天气」。

**你自己拼出来的句子会被记住**（存在词库的 `user_phrase` 表里，键就是你敲的那串字母）。
所以「词库里没有、整句也拼不出来」的句子，只要你分段挑过一次，下次就能一步上屏 ——
上面例子里的「你好马」就是这么来的（第一次是挑「你好」+「马」拼的，第二次一次空格就出）。

「上屏这段 + 剩下的预编辑」是**在同一批协议状态里**发给应用的（一批里既有
`commit_string` 又有 `preedit_string`）。分两批发的话，有的应用会把第二批的预编辑吃掉 ——
表现就是"前面的字上屏了，后面那截输入框里没提示"。

几个细节：

* 只有**两次以上**的选择才算"你自己拼的句子"（只挑一次的话，词库里本来就有，记了也是噪音）。
* 每挑一段也照常记进 `user_word`（选过的词下次排更前）。
* 按 Esc 取消、或者把拼音删光，这次就不记了 —— 你不要它了。
* 想清空记性：`sqlite3 ~/.local/share/pliers/dict.db "delete from user_phrase"`；
  只想删某一条的话，把它打到候选框里**按 `Del`**（选中的那个）。

## `Del`：删掉自己拼出来的词

候选框里按 `Del` 删的是**自己拼出来的那个词**，做三件事（`user_phrase` / `user_word` / `user_hidden` 三张表）：

* `user_phrase` 里那一行真删掉；
* 清掉"我用过它"的偏好；
* 记进 `user_hidden` 黑名单 —— 不记的话整句候选会立刻把同一个词拼回来，看着像没删掉。
  黑名单**只对"不是词库里的"候选生效**：词库里本来就有那个词条的话，它照样在候选里
  （早先版本误删留下的黑名单因此自动失效，不用手工清库）。

删完候选列表会**接着显示**（选中回到第一个），所以"删没删掉"一眼就能看见，
也不至于手一抖接着按 `Del` 就把下一个也删了。**词库里原本就有的词删不了**，
只会回一句「不是自己拼的，删不了」—— 那是导入进来的数据。
删错了想找回来：`sqlite3 ~/.local/share/pliers/dict.db "delete from user_hidden where text='你好啊'"`。

**组词当中 `Del` 一律被吃掉、绝不转发**（回一句「没有能删的候选」也认）。
漏给应用的话，在终端里就是屏幕上刷出一串 `^[[3~`（Del 的转义序列）。没在组词时
`Del` 照旧是应用的键（删它自己的字）。
